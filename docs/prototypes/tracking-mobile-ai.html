Signal Confidence in the Officer's Hand

Where a live tracking-status icon belongs in a field app's top bar — and why putting the system's own confidence in front of the person carrying the device is the cheapest feedback loop in the whole operation.

No real data

Client name, site addresses and codes, shift identifiers, personnel initials, repository and file paths, internal component names, the assistant's product name and the corporate palette have all been replaced with neutral placeholders. The mock, the interactions, the reasoning and the recommendation are unchanged. Substitution table at the end.

The main idea

The icon is a false-positive reducer, not chrome

A field officer's phone reports its position continuously while on shift. That signal carries a confidence — sometimes the fix is good, sometimes the satellite geometry has collapsed and the position is a guess, sometimes the app has stopped reporting altogether.

Today the officer cannot see any of it. The confidence is visible only downstream, to the operations centre and to the automation reading the feed. So when the signal degrades, the officer — the one person who could fix it in five seconds by reopening the app — is the only participant who does not know.

An officer who can see that the signal has gone uncertain can restart the app before the operations centre ever receives an event.

The argument the whole placement study exists to serve

That reframes the work. It is not a request to add an icon to a toolbar; it is a proposal to close a control loop at its cheapest point. Placement only matters because the icon has to be glanceable on every screen, in a fixed position, without a label for that loop to close.

Try the placement

Tracking status preview

Colours mirror the operations map's existing ping-accuracy semantics: green = confirmed fine, amber = position uncertain, red = a problem. An officer who can see amber restarts the app before the operations centre ever gets an event — this icon is a false-positive reducer, not chrome.

The change, if you go with A

Insert the icon into the home screen's action list; the shared bar renders it just left of the bell on both profiles. Colour it by live state, and let a tap open a status sheet — permissions, last report, restart help.

// home screen — the action list handed to the shared bar
actions: [
  if (profileLoaded)
    AccountAvatarButton(),
  if (deviceProfile == COMPANY_DEVICE ||
      contractPermissions.tracking == true)
    TrackingStatusIcon(),   // <- new, sits between avatar and bell
]
// the shared bar appends the notifications bell after this list,
// so the bell stays rightmost on every screen. Nothing else changes.
Watch-outs: the company-device title is long — with the rating on the left and three actions on the right it still fits at this width, but do not add a fourth; platform guidance caps top-bar actions at about three. Keep a 48 dp touch target. And grey the icon when off-shift rather than removing it, so officers learn one fixed position.

The states

Four states, and the one that earns the feature

Active

Reporting, accuracy within tolerance. Nothing to do.

Low accuracy

The state that justifies the whole feature. Still reporting, but the position cannot be trusted — and it is actionable by the officer alone.

Not tracking

Should be reporting and is not — permission revoked, service killed, or the app force-closed.

Off / no shift

Correctly inactive. Rendered grey rather than removed, so the position is learned.

Absence renders as a state, not as nothing

The icon greys out when off-shift instead of disappearing. Two reasons: a control that comes and goes is never learned, and — more importantly — "off" and "broken" must look different. A missing icon collapses those two into one.

The flow

Two paths for the same degraded signal

This is the connection between the patrol in the field and the automation watching it. The same event — accuracy collapsing mid-patrol — travels one of two routes depending on whether anyone in the field can see it.

Constraints this inventory produced

  • The bell is the one fixed position in the app. Anything that wants to be found reliably should sit next to it, not somewhere new.
  • About three actions is the practical ceiling for a top bar under standard platform guidance — and the company-device title is already long.
  • Minimum 48 dp touch target, preserved at the icon's small visual size.
  • Never remove the icon when inactive. Grey it, so its position is always the same place.

One judgement call before sharing

This version carries no client, personnel or source data. What it still reveals is a design approach and an operational weakness — that a degraded position signal currently reaches the control room before it reaches the officer. That is fair to discuss as professional work, but it is a decision, not a redaction: choose deliberately whether the audience should see it.
